# A saved and resumed run diverges from an unbroken one

**Status:** closed - (the save carries the material demand the last resource throttle saw and keeps dict order; a resume from before the late game now plays on as the unbroken run does)

Rome 100 AD seed 1, events on, fog off, stepped year by year with a digest of the simulation state after each year (the digest in `sim/perf_fingerprint.py`). A run that is saved and loaded at some year (`save_state` then `load_state` into a freshly built `Sim`) has a different digest from the unbroken run from the first year after the load, in the late game (found around AD 217). Two resumed runs that stop and resume at the same years agree with each other, so the difference is the round trip, not nondeterminism. Rule 4.6 of CLAUDE.md requires a save to round-trip within a build; a `--session` game does this every command.

Why it matters: every `--session` game is a chain of save and load, so it plays a different game from the one a single process would; any measurement made across a resume is not comparable with one made without.

What it would take: stop an unbroken run and a saved-and-reloaded copy at the same year, step both once, and diff the state field by field to find which field is not carried (a cache that decides a result, or a field outside the save's field list). Reproduce with any script that builds `perf_fingerprint.build(dict(civ="rome_100ad", seed=1, years=300, events=True, fog=False))`, steps to the late 100s, saves, loads and compares. Related: 396 (the determinism guard cannot see hidden carried state).

Resolution: the next year's project prices read `household._material_demand_cache`, the demand the last `resource_throttle` saw, before throttling again; a loaded game started with none and read the current demand instead, so the first priced project after a load could be billed differently (found by transplanting each household attribute of the live game into a loaded one and comparing the next year's digest). It is now a field of the economy state (`material_demand_at_last_throttle`) written at save and restored at load. The save also stopped sorting dict keys, so a loaded dict iterates in the order the live one did (float sums follow it). Tests: `sim/tests/test_complaint_470_save_round_trip.py`, and the every-year guard `sim/tests/test_save_round_trip_every_year.py`; the guard fails on the old code at year 10 of Rome seed 1. Measure: save an unbroken Rome seed 1 run at some year with `perf_fingerprint.build`, load it into a fresh build, and compare `perf_fingerprint.digest(perf_fingerprint.state_of(game))` for each following year. Caches other than this one were checked by clearing each in a live game: none decided a result.

Second cause, found after the capital-market and late-game-speed merges (the guard failed at year 37): `household_demand_ratios` cached its result keyed on population and income rounded to a thousandth but computed it from the exact values at the time, so the live value depended on when it was last recomputed and a loaded game computed a slightly different one (a different market price ratio, hence revenue, credit limit and interest). It now computes from the rounded key, so the value is a function of the key. This changes unbroken results slightly (inputs are rounded); it is the only change in unbroken behaviour from this complaint.

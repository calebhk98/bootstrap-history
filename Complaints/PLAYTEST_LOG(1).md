# Blind Playtest Log — One Person, and Everything They Know

Rules: blind playthrough; no source/data/docs/previous-session notes read. Goal is to play to win while recording expectations before outcomes.

## Observations

1. **Main menu / options discoverability.** The opening premise is concise and immediately establishes the core constraint: "Knowing how a thing works is free. Building it is not" and that costs include "your own hours, other people's hours, money, materials, and years." This gives me a strong expectation that labor, capital, materials, and time are distinct bottlenecks rather than one abstract resource.

2. **Options menu.** I checked this first as recommended. It clearly distinguishes program preferences from per-playthrough settings: "What a single playthrough is (civilisation, starting kit, fog, mortality, the horizon) is asked when that game starts, not here." I left defaults unchanged: save location `/home/oai/.rome-saves`, width 76, 30 rows/table, tutorial text on. This is clear UI so far.

3. **Civilisation choice.** I chose **Roman Empire under Trajan, 100**. Before seeing mechanics, I expect Rome to be a balanced/high-capacity start: easier access to money, labor, infrastructure, and government cooperation than Scandinavia, but with social/institutional penalties around manual work and slavery. I am choosing it partly because its listed price level is the 1.00x baseline, which should make later cost judgments easier.

4. **Rome briefing reaction.** The line "Not the ideas. The instruments" is a strong model promise. Before playing, I expect measurement, precision/tolerances, vacuum capability, and purification to function as foundational capability gates across many later technologies. If late technology bypasses these cheaply, that would contradict the briefing.

5. **Fog of war.** Keeping **ON**. I expect this to prevent route optimization from hidden tree knowledge and force decisions based on visible summaries and experimentation. This is desirable for the blind test.

6. **Starting income choice.** Chose **merchant — 4,000 denarii**, the middle of the seven listed options. Expectation: enough capital to make an intentional opening plan, but not enough to brute-force labor/material bottlenecks. The text explicitly claims money mostly changes the first fifty years and cannot make me a magician; I will watch whether that remains true.

7. **Mortality.** Leaving mortality **OFF**, i.e. immortal founder, per playtest setup. This means I will judge time costs as opportunity costs and pace/balance rather than against a human lifespan ceiling.

8. **Goal menu.** The game now offers 17 victory goals, with visible dependency closure and theoretical minimum years. I chose **1) Grown and alloy junction transistors** (closure 168, floor 142y), the original/default target. Expectation: this should exercise the broadest set of interacting systems and expose long-run bottlenecks better than a short lifetime goal.

9. **Horizon.** Chose **Standard — 500 years**. The UI says difficulty changes only the calendar, not costs or failure odds. For a blind difficulty test, Standard is the correct baseline; Challenge would confound learning friction with intentionally tight timing.

10. **Help command discoverability.** `help commands` is excellent and explicitly reveals several tools I would otherwise miss: `score`, `values`, `risk`, `allocate`, `bounty`, `policy`, and manual `save/load`. This directly addresses the historical problem of players finishing without knowing tools existed. I am glad the tutorial explicitly tells me to check it.

11. **Opening plan before action.** Scientific method appears highest leverage because its description says "Multiplier on every research node thereafter" and almost everything rests on it. Units/standards also says almost everything rests on it. Horse collar looks like a politically safe early revenue concern (650–1,100 den/yr guessed revenue vs 150 upkeep), while identity cover is expensive but reduces future suspicion. Planned order: method + standards, establish cash flow, then cover identity unless risk forces cover earlier.

12. **Save/load test plan.** Before spending anything, manually save a snapshot, start scientific method, then reload the snapshot. Expected result: money/hours/project state return exactly to pre-start values. This is intentionally a rollback test, not a strategic change.

13. **Save command mistake / UX.** I tried `save /home/oai/.rome-saves/playtest_manual.json`; the game refused it: "a save file must be a relative path, not an absolute one. Try save mygame.json". This is a good error message: it says both what was wrong and exactly how to correct it. Because my save failed, the subsequent `start scientific_method` affected the real session. That is acceptable because it was already my intended first strategic action.

14. **Start semantics surprise, positive.** Starting scientific method did not immediately consume the displayed 230 den or 350 founder-hours. Instead it created a running project "waiting on your hours" with the bill still owed. The game explicitly explains calendar floors are non-exclusive and recommends parallel preparation. I had expected `start` to reserve/consume resources immediately; this model is more flexible and, so far, makes sense.

15. **Manual save/load verified.** `save playtest_manual.json` succeeded. I started `units_standards`, saw it appear as a second running project, then `load playtest_manual.json` restored the state to exactly one running project (`scientific_method`). Manual rollback works in this environment; this lowers the risk of autosave/environment failure.

16. **First real bundle, prediction before stepping.** I will start `units_standards`, `horse_collar`, and `identity_cover` alongside `scientific_method`. Combined founder-hour requirements are 1,350h, below my 2,000h/year. I expect the 0.5y standards and cover projects and the 1y horse collar to finish during/at the end of the first year if they do not fail; scientific method should not finish before year 102 because of its 2-year calendar floor. I expect cash after paying all four and living costs to be roughly 1,000 den, so opening horse collar quickly is important for cash flow.

17. **Year 100 outcome.** Prediction mostly correct: `units_standards`, `horse_collar`, and `identity_cover` all completed during the first year; no failures. `scientific_method` consumed all its founder-hours but remains calendar/money-paced with 115 den still owed and about one more year. Money is 1,101 den. The horse collar concern is shown as 900 earn / 150 cost per year, exactly the midpoint of its earlier 650–1,100 estimate.

18. **Open/close decision.** I will open `horse_collar` because +~750 den/yr net is now crucial. I will open `identity_cover` because its description explicitly says to keep it open for protection/standing effects. I will *not* open `units_standards`: its knowledge is already permanent and I see no listed continuing capability that justifies 30 den/yr upkeep.

19. **Target menu breadth.** The new-game menu offers 17 victory targets, from `Establish experimental science` (closure 1, floor 2y) through mid-scale lifetime/generational targets such as germ theory, state patronage, electricity, literacy, epidemic control, steam, interchangeable manufacturing, navy and telegraph, to civilisation-scale steel, radio, fertiliser, flight, transistors and maximum literacy. This is a strong addition: it turns the same simulation into short, medium and long campaigns without changing the underlying costs/risk model.

20. **Horizon menu.** Horizon is explicitly the difficulty control and can be changed later: Challenge 400y, Standard 500y, Relaxed 650y, Endless, or an exact custom number. I like that difficulty does not secretly alter prices/failure rates; it makes comparison between runs intelligible.

21. **Command surface.** `help commands` exposes 35 distinct top-level command words by my count (counting paired verbs separately: hire/fire/train/commission, mothball/restore, save/load), plus topic-specific help. Several are strategically important rather than mere UI conveniences: `money`, `values`, `risk`, `population`, `quote`, `allocate`, `bounty`, `policy`, `score`, and `log`. The interface is notably agent-friendly: help explicitly documents one-command-per-invocation use with `--session`, persistence after every command, and even JSON command input.

22. **Fog/tree-size behavior.** `score` explicitly withholds total technology coverage/tree size under Fog. Current visible lower bound is already >352 items (142 built at load plus 210 currently startable), before blocked/heard-of items, so this is a genuinely large tree. I will not inspect data files to learn the exact count.

23. **Initial visible technology shape.** Current 210 startable projects span 20 subjects: textiles (54), finance (26), roads/bridges/canals (20), remaining arts (20), power/precision (15), deep farming (11), household (10), metallurgy (9), deep transport (9), mathematics/method (7), medicine/biology (7), agriculture/food (6), construction (5), signals/media (3), electricity (2), glass/optics (2), briefing (1), society/politics (1), printing/information (1), and one miscellaneous. The breadth makes this feel like a society simulator rather than a conventional narrow tech tree, though 210 immediately-startable options risks paralysis.

24. **Population model first impression.** The game distinguishes 65M imperial population, ~7.8M urban population, and a ~50k-person local labour market actually reachable by my household. Specialist availability is sharply constrained (e.g. only about one reachable millwright, ~3 engravers/glassblowers, ~6 scholars/scribes) while common trades number in the hundreds locally. This is one of the most convincing pieces so far because it prevents '65 million Romans therefore I can hire 10,000 precision craftsmen tomorrow.'

25. **Economy first impression.** Current cost of living is 252.7 den/yr and I have only 714 den after the opening projects. This makes cash a near-term hard constraint even though it is explicitly not intended to replace calendar, skill, material or political constraints. My horse-collar venture is therefore strategically important: without reliable income, I cannot afford patronage or sustained parallel research.

26. **Politics first impression.** Politics is currently concrete rather than ornamental: state suspicion blocks visible agricultural projects, patronage appears as a high-leverage unlock, identity cover affects standing/protection, and future historical shocks interact with knowledge loss and staff survival. This is promising because 'politics' is functioning as access/risk/capacity rather than a generic approval meter.

27. **LLM-first interface impression.** This is unusually well suited to an LLM/agent. Every important state is textual, commands are composable and searchable, errors are corrective, `why`/`available`/`stuck` expose reasoning-relevant state, pagination/filtering prevents huge dumps, and save persistence means one-shot invocations work. A human gets the same power, but an LLM benefits more because it can systematically compare 200 choices, maintain a written plan, query exact constraints, and exploit structured natural-language output without needing a graphical spatial memory.
